# چرا (Chera)

**چرا** یک ابزار خط فرمان برای عیب‌یابی شبکه است که توضیح می‌دهد *چرا* یک سرویس در دسترس نیست، نه فقط *اینکه* در دسترس نیست.

[English](README.md) · [نحوه کار (انگلیسی)](docs/how-it-works.md) · [مشارکت (انگلیسی)](CONTRIBUTING.md)

---

برنامه‌نویس‌هایی که پشت شبکه‌های فیلترشده (در ایران و جاهای دیگر) کار می‌کنند، مدام با سرویس‌هایی روبه‌رو می‌شوند که «کار نمی‌کنند»: GitHub، PyPI، npm، Docker Hub، Hugging Face و APIهای هوش مصنوعی. ابزارهایی مثل `ping` و `curl` فقط می‌گویند «ناموفق». اما علت واقعی می‌تواند هر کدام از این‌ها باشد:

- مسموم‌سازی DNS، یا ربودن پرس‌وجوهای DNS در مسیر
- مسدودسازی IP
- فیلترینگ اتصال‌های TLS بر اساس SNI
- صفحه مسدودسازی دولتی
- مسدودسازی کشور شما **توسط خود سرویس‌دهنده** (تحریم یا محدودیت‌های صادراتی)
- محدودسازی سرعت (throttling)
- خرابی اتصال محلی
- قطعی معمولی در سمت سرویس‌دهنده

هر علت راه‌حل متفاوتی دارد و حدس زدن ساعت‌ها وقت می‌گیرد. چرا روی هر سرویس آزمون‌های لایه‌به‌لایه اجرا می‌کند و محتمل‌ترین علت را همراه با شواهد، سطح اطمینان و قدم بعدی پیشنهادی گزارش می‌دهد.


*خروجی بالا فقط برای نمایش است و نشان می‌دهد علت‌های مختلف چطور کنار هم گزارش می‌شوند. آنچه شما می‌بینید به شبکه‌تان بستگی دارد.*

## ویژگی‌ها

- **یک نتیجه برای هر سرویس** با سطح اطمینان (زیاد، متوسط، کم) و شواهد پشتیبان.
- **عیب‌یابی لایه‌ای**: شبکه محلی، DNS (سیستمی، UDP ساده و DNS-over-HTTPS)، TCP، TLS/SNI، HTTP، آزمون اختیاری سرعت و صفحه‌های وضعیت رسمی.
- **تفکیک فیلترینگ از تحریم**: وقتی خود سرویس‌دهنده منطقه شما را رد می‌کند، نتیجه `PROVIDER_GEO_BLOCK` است، چون تغییر DNS یا شبکه آن را حل نمی‌کند.
- **پیش‌تنظیم‌ها (preset)** برای GitHub، Python، Node، Docker، Hugging Face، APIهای هوش مصنوعی، Go و Rust که در فایل YAML تعریف شده‌اند و قابل گسترش‌اند.
- **خروجی برای انسان و ماشین**: جدول رنگی، `--json` و `--markdown` برای چسباندن مستقیم در یک issue در GitHub.
- **فارسی و انگلیسی** (`--lang fa`)، با تشخیص خودکار از تنظیمات زبان سیستم.
- **یک فایل اجرایی مستقل** بدون هیچ وابستگی، برای لینوکس، macOS و ویندوز (amd64 و arm64).
- **ملایم و حافظ حریم خصوصی**: فقط چند اتصال برای هر سرویس، بدون اسکن، بدون تلاش مجدد و بدون ارسال هیچ داده‌ای به هیچ جا.

## نصب

### فایل‌های آماده (پیشنهادی)

فایل مناسب سیستم خود را از [صفحه releaseها](https://github.com/assaabriiii/chera/releases) دانلود کنید، آن را با `checksums.txt` بررسی کنید و فایل `chera` را در `PATH` قرار دهید.

</div>

```sh
# نمونه برای لینوکس / macOS (VERSION، OS و ARCH را جایگزین کنید)
curl -LO https://github.com/assaabriiii/chera/releases/download/vVERSION/chera_VERSION_OS_ARCH.tar.gz
curl -LO https://github.com/assaabriiii/chera/releases/download/vVERSION/checksums.txt
sha256sum --ignore-missing -c checksums.txt     # macOS: shasum -a 256 --ignore-missing -c checksums.txt
tar xzf chera_VERSION_OS_ARCH.tar.gz
sudo mv chera /usr/local/bin/
```

<div dir="rtl">

در ویندوز فایل `.zip` را دانلود کنید، هش آن را با `Get-FileHash` مقایسه کنید و `chera.exe` را استخراج کنید.

اگر خود GitHub از شبکه شما به‌سختی در دسترس است، از کسی بخواهید یک release را همراه با `checksums.txt` برایتان بفرستد: فایل اجرایی هیچ وابستگی ندارد و checksum ثابت می‌کند که تغییری نکرده است.

## استفاده

</div>

```sh
chera                          # اجرای پیش‌تنظیم پیش‌فرض برنامه‌نویسی
chera github.com               # بررسی یک میزبان
chera pypi.org files.pythonhosted.org
chera --preset ai              # APIهای هوش مصنوعی
chera --preset python          # PyPI
chera --preset docker          # Docker Hub
chera --preset all             # همه مقصدهای داخلی
chera --list-presets           # فهرست پیش‌تنظیم‌ها
chera --verbose github.com     # همه آزمون‌ها و شواهد خام
chera --json                   # خروجی ماشینی
chera --markdown > report.md   # گزارش آماده برای issue
chera --speed                  # بررسی محدودسازی سرعت
chera --lang fa                # خروجی فارسی
```

<div dir="rtl">

### گزینه‌ها

| گزینه | پیش‌فرض | توضیح |
|---|---|---|
| `--preset NAME` | `dev` | پیش‌تنظیمی که اجرا می‌شود. |
| `--json` | | خروجی JSON. |
| `--markdown` | | گزارش Markdown برای issueهای GitHub. |
| `-v`، `--verbose` | | نمایش همه آزمون‌ها و شواهد خام. |
| `--timeout D` | `5s` | مهلت هر عملیات شبکه. |
| `--proxy URL` | | عبور اتصال‌های TCP از یک پراکسی (`http://host:port` یا `socks5://host:port`). |
| `--resolver R` | | یک `IP[:port]` جایگزین DNS سیستم به عنوان سرور مورد آزمون می‌شود؛ یک آدرس `https://` به عنوان مرجع DoH مورد اعتماد اضافه می‌شود. |
| `--speed` | | اندازه‌گیری زمان دست‌دهی و سرعت دانلود برای تشخیص محدودسازی. |
| `--lang en\|fa` | از تنظیمات زبان | زبان خروجی. |
| `--concurrency N` | `8` | تعداد مقصدهایی که هم‌زمان بررسی می‌شوند. |
| `--no-color` | | غیرفعال کردن رنگ (`NO_COLOR` هم رعایت می‌شود). |
| `--presets FILE` | | فایل YAML پیش‌تنظیم‌های اضافه. |
| `--signatures FILE` | | فایل YAML امضاهای اضافه. |

کد خروج: `0` وقتی همه مقصدها `OK` هستند، `1` وقتی دست‌کم یکی نیست، و `2` برای خطای استفاده یا پیکربندی.

## نتیجه‌ها (verdict)

هر مقصد دقیقاً یک نتیجه اصلی می‌گیرد. اگر در مسیر مشکل دومی هم پیدا شود (مثلاً مسموم بودن DNS در کنار فیلترینگ SNI)، با عنوان «همچنین» نمایش داده می‌شود.

| نتیجه | معنی | معمولاً چه کمک می‌کند |
|---|---|---|
| `OK` | سرویس اصلی از مسیر تأییدشده پاسخ داد. | مشکلی نیست. |
| `LOCAL_NETWORK_DOWN` | رابط شبکه فعال یا مسیر پیش‌فرض وجود ندارد، یا هیچ میزبان شناخته‌شده‌ای در دسترس نیست. | اول Wi-Fi، کابل، مودم یا روتر را درست کنید. |
| `DNS_POISONED` | DNS شما آدرس صفحه مسدودسازی، آدرس خصوصی، آدرسی که این سایت را سرو نمی‌کند، یا «نام وجود ندارد» برمی‌گرداند، در حالی که DNS-over-HTTPS پاسخ درست می‌دهد. | استفاده از DNS رمزنگاری‌شده (DoH/DoT). |
| `DNS_INTERCEPTED` | ترافیک DNS در مسیر ربوده می‌شود؛ تغییر آدرس سرور DNS کمکی نمی‌کند. | استفاده از DNS رمزنگاری‌شده (DoH/DoT). |
| `IP_BLOCKED` | اتصال به آدرس‌های درست سرویس به پایان مهلت می‌رسد: بسته‌ها بی‌صدا دور ریخته می‌شوند. | تغییر DNS کمکی نمی‌کند؛ از mirror استفاده کنید. |
| `CONNECTION_RESET` | اتصال به آدرس‌های درست فعالانه رد یا ریست می‌شود. | تغییر DNS کمکی نمی‌کند؛ از mirror استفاده کنید. |
| `SNI_FILTERED` | دست‌دهی TLS درست پس از ClientHello برای نام واقعی قطع می‌شود، در حالی که همان آدرس به نام دیگری پاسخ می‌دهد. | تغییر DNS کمکی نمی‌کند؛ از mirror استفاده کنید. |
| `TLS_INTERCEPTED` | گواهی معتبر نیست یا توسط یک محصول بازرسی TLS صادر شده است. | رمز عبور و توکن نفرستید؛ از مدیر شبکه بپرسید. |
| `BLOCK_PAGE` | پاسخ، صفحه مسدودسازی دولتی یا ISP است. | فیلترینگ شبکه؛ از mirror استفاده کنید. |
| `PROVIDER_GEO_BLOCK` | خود سرویس **اصلی** منطقه شما را رد می‌کند (HTTP 403/451 با پیام «منطقه پشتیبانی نمی‌شود»). | مشکل شبکه نیست: تغییر DNS یا شبکه آن را حل نمی‌کند. |
| `THROTTLED` | سرویس کار می‌کند اما به‌شدت کندتر از میزبان مبناست (`--speed`). | بعداً دوباره امتحان کنید یا از mirror استفاده کنید. |
| `UPSTREAM_OUTAGE` | مسیر شبکه سالم است اما سرویس خطای 5xx می‌دهد یا صفحه وضعیتش حادثه‌ای را گزارش می‌کند. | صبر کنید و صفحه وضعیت را ببینید. |
| `INCONCLUSIVE` | علت روشنی پیدا نشد. | با `--verbose` اجرا کنید و گزارش `--markdown` را به اشتراک بگذارید. |

پیشنهادها فقط علت و راه‌حل‌های عمومی (DNS رمزنگاری‌شده، mirror بسته‌ها، صبر برای سرویس‌دهنده) را توضیح می‌دهند. چرا هیچ سرویس دور زدن فیلترینگ مشخصی را همراه ندارد یا پیشنهاد نمی‌کند.

### سطح اطمینان

- **زیاد**: شواهد به یک علت اشاره می‌کنند، مثلاً آدرس شناخته‌شده صفحه مسدودسازی در پاسخ DNS، یا ریست شدن SNI در حالی که SNI خنثی روی همان آدرس کار می‌کند.
- **متوسط**: شواهد با این علت سازگارند اما توضیح دیگری هم ممکن است (مثلاً اتصال ردشده ممکن است از سروری باشد که خاموش است).
- **کم**: بهترین حدس؛ خروجی `--verbose` را ببینید.

## تشخیص چطور کار می‌کند

چرا برای هر مقصد این لایه‌ها را به ترتیب اجرا می‌کند. هر لایه شواهدی تولید می‌کند و موتور تصمیم‌گیری آن‌ها را کنار هم می‌گذارد. راهنمای کامل در [How it works](docs/how-it-works.md) آمده است.

۱. **شبکه محلی**: رابط‌ها، مسیر پیش‌فرض، دسترسی به چند میزبان شناخته‌شده، و تشخیص متغیرهای پراکسی، تنظیمات پراکسی سیستم و رابط‌های VPN تا نتایج اشتباه خوانده نشوند.

۲. **DNS**: پرس‌وجو از DNS سیستم، UDP ساده به سرورهای عمومی و DNS-over-HTTPS (Cloudflare، Google، Quad9 با آدرس IP ثابت). پاسخ‌ها با آدرس‌های شناخته‌شده صفحه مسدودسازی (مثل `10.10.34.34` تا `10.10.34.36`) و بازه‌های خصوصی مقایسه و با DoH سنجیده می‌شوند. یک پرس‌وجو به آدرسی که هیچ سرور DNS ندارد، ربوده شدن DNS را آشکار می‌کند.

۳. **TCP**: اتصال به پورت 443 روی آدرس‌های درست (از DoH) و تفکیک «پایان مهلت» (دور ریختن بسته‌ها) از «ریست».

۴. **TLS / SNI**: دست‌دهی با SNI واقعی و اعتبارسنجی گواهی. اگر روی شبکه شکست بخورد، با SNI خنثی و بدون SNI دوباره امتحان می‌شود؛ اگر آن‌ها موفق شوند، نام سایت فیلتر شده است.

۵. **HTTP**: درخواست یک آدرس سبک از آدرس تأییدشده و دسته‌بندی پاسخ: صفحه مسدودسازی، مسدودسازی جغرافیایی توسط سرویس‌دهنده، خطای سرور یا پاسخ عادی.

۶. **محدودسازی سرعت** (`--speed`): مقایسه زمان دست‌دهی و سرعت دانلود با یک دانلود مبنا.

۷. **بررسی قطعی**: وقتی مسیر سالم است اما سرویس خطا می‌دهد، صفحه وضعیت رسمی آن پرسیده می‌شود.

## پیش‌تنظیم‌ها

| پیش‌تنظیم | مقصدها |
|---|---|
| `github` | github.com، api.github.com، raw.githubusercontent.com، objects.githubusercontent.com، codeload.github.com |
| `python` | pypi.org، files.pythonhosted.org |
| `node` | registry.npmjs.org |
| `docker` | registry-1.docker.io، auth.docker.io، production.cloudflare.docker.com |
| `huggingface` | huggingface.co، cdn-lfs.huggingface.co |
| `ai` | api.openai.com، api.anthropic.com، generativelanguage.googleapis.com |
| `go` | proxy.golang.org |
| `rust` | crates.io |
| `dev` (پیش‌فرض) | github، python، node، docker، go |
| `all` | همه مقصدهای داخلی |

پیش‌تنظیم‌ها در [`internal/presets/presets.yaml`](internal/presets/presets.yaml) تعریف شده‌اند و داخل فایل اجرایی قرار دارند. برای افزودن پیش‌تنظیم خودتان، فایل `presets.yaml` را در پوشه تنظیمات کاربر (`~/.config/chera/` در لینوکس، `~/Library/Application Support/chera/` در macOS، `%AppData%\chera\` در ویندوز) بسازید یا از `--presets FILE` استفاده کنید. نمونه در [README انگلیسی](README.md#presets) آمده است.

امضاهای مسدودسازی (آدرس‌های DNS تزریقی، صفحه‌های مسدودسازی، پیام‌های مسدودسازی جغرافیایی و محصولات بازرسی TLS) در [`internal/signatures/signatures.yaml`](internal/signatures/signatures.yaml) هستند و به همین روش با `signatures.yaml` یا `--signatures FILE` قابل گسترش‌اند.

## حریم خصوصی

چرا فقط با سرویس‌هایی که بررسی می‌کند، سرورهای DNS عمومی ذکرشده، میزبان‌های مبنا (`1.1.1.1`، `8.8.8.8`، `9.9.9.9`)، صفحه‌های وضعیت رسمی مقصدها و در صورت استفاده از `--speed` با `speed.cloudflare.com` ارتباط برقرار می‌کند. هیچ داده‌ای ارسال یا بارگذاری نمی‌کند. گزارش‌های JSON و Markdown آدرس IP محلی شما را ندارند و از متغیرهای پراکسی فقط نامشان را ذکر می‌کنند، نه مقدارشان را.

## مشارکت

مشارکت شما بسیار ارزشمند است، به‌خصوص پیش‌تنظیم‌های جدید و امضاهای صفحه مسدودسازی یا مسدودسازی جغرافیایی از شبکه‌هایی که هنوز ندیده‌ایم. راهنما در [CONTRIBUTING.md](CONTRIBUTING.md) آمده است. گزارش تشخیص اشتباه را می‌توانید به فارسی هم بنویسید.
